# Security and product audit — 2026-09-06

Scope: Zig/Zap backend, SurrealDB repository, browser controller and WASM,
tests, CI, deployment files, and read-only inspection of task.micutu.com.
Production accounts are not used for destructive tests. Findings below begin
as source/configuration observations; reproduction and remediation evidence is
recorded as each stage completes. This is not a claim that all vulnerabilities
have been found or that an external penetration test has been completed.

## Priority findings

| ID | Severity | Evidence at baseline 958ea41 | Consequence / action |
| --- | --- | --- | --- |
| S01 | Critical impact, conditional on code execution | systemd runs as `micu`, a Docker group member; Docker socket is group writable and not hidden from the unit | Application compromise can reach host administration and other applications. Move to a dedicated service identity and isolated release directory. |
| S02 | High | `verifyCsrfToken` accepts any `Bearer ` header before checking the cookie, while authentication prefers the cookie | Mixed credentials bypass the session's CSRF validation. Require CSRF whenever the session cookie is present. Browser exploitation depends on origin/CORS and request context. |
| S03 | High | Reset token is read before hashing; password UPDATE predicates only on user ID; session revocation is separate and best effort | Concurrent uses can both succeed; a partial failure can leave old sessions valid. Consume the token and revoke sessions in one transaction. |
| S04 | High | Parent creation checks write access but not workspace equality; deletion deletes all rows with that parent | A member of two workspaces can create a cross-workspace dependency that lets another workspace's writer delete the child. Enforce same-workspace parentage and scoped deletion. |
| S05 | Medium | Update passes `assignee_id` straight into the database, unlike create | Task assignment can point to an outsider or nonexistent account. Validate membership on both paths. |
| S06 | Medium | Every successful PUT of a completed recurring task spawns a new task | Editing notes or retrying completion creates duplicate work. Make recurrence creation atomic and idempotent. |
| S07 | Medium | API does not emit `Cache-Control: no-store` | Account/task/export responses lack explicit protection from private or intermediary caching. Add at backend and proxy. |
| S08 | High operational | Integration cleanup kills listeners by port, even after refusing an occupied port; smoke response uses a shared `/tmp` filename | Tests can stop another service or overwrite a symlink target. Track only owned PIDs and use private temporary files. |
| S09 | High impact | Application database credentials are root-level | Query or application compromise has unnecessary database administration scope. Separate runtime and migration identities. |
| S10 | Medium | SQL HTTP client retries all operations after ambiguous transport errors | Non-idempotent writes can be replayed. Remove automatic write retries. |
| S11 | Medium | Schema initialization continues after exhausting failures; task-list DB failure returns success with an empty array | Broken deployments and outages can look healthy or look like data loss. Fail startup closed and surface errors. |
| S12 | Medium | Signup explicitly says `Email already exists` | Account enumeration remains possible despite SECURITY.md claiming uniform signup responses. Redesign registration response/session flow before claiming protection. |

## Product and maintainability gaps

- Board completion state drifts on create and bodyless toggle.
- Nested subtasks can be created beyond the one level the UI renders/deletes.
- Editing a reminder deadline does not rearm reminder delivery.
- JSON export omits newer status/assignment/parent/recurrence fields.
- Mobile checks need narrow widths, board/editor states, dark theme, keyboard
  focus and long content. The current WASM assertion only checks API presence.
- Saved views, Today/Upcoming, useful empty/error states and offline metadata
  parity are higher value next steps than adding unrelated framework tooling.
- README describes an app+DB Compose stack, but Compose starts only the DB.
  Deployment examples use obsolete Zig and database versions. npm lockfile is
  ignored; CI dependencies/actions are not all pinned by content digest.
- Invitation acceptance, account deletion and several permission checks span
  multiple DB statements without a transaction; race tests need expansion.
- Quotas, pagination, durable mail delivery, backup restore evidence, alerting,
  MFA/passkeys and recovery procedures need tracked work.

## Threat model and incident readiness (ciso-review)

Top risks: elevation of privilege through the runtime Unix identity; tampering
across workspace boundaries and credential races; denial of service from
password hashing, unbounded account/workspace growth and database requests.

Worst case: account email addresses, password hashes, task contents, workspace
membership and secrets readable by the service identity; with Docker access,
other services on this VPS may also be affected. User count, incident cost and
annualized loss are unknown; no invented financial estimate is appropriate.

Detection observed: systemd/nginx logging and protected metrics. Alert routing,
current mean detection time and a tested on-call procedure are not established
by repository evidence. Target: alert within 5 minutes on sustained errors,
restart loops or abnormal authentication failures; name the operator and test
delivery before calling this implemented.

Vendors/components: VPS hosting, Cloudflare, SurrealDB, Zap/facil.io, SMTP,
GitHub Actions and test browser distribution. No new data vendor is proposed.
Contracts, data-processing agreements and regulatory scope are not established
by source inspection. An incident involving personal data requires a factual
assessment of applicable notification duties, not an automatic claim of
compliance.

Verdict: mitigate confirmed findings, verify in isolation, preserve a rollback
release and rehearse the incident procedure before production promotion.

## Verification log

- Live HTML uses CSP without `unsafe-inline`, HSTS, nosniff, frame denial and
  Cloudflare proxying. Direct unauthenticated task read returns 401.
- Backend and database listen on loopback. `nginx -t` succeeds and the active
  task vhost matches its versioned copy.
- `.env` and its backup are mode 0600 and Git-ignored. No contents are included
  in this report. No destructive live exploit has been attempted.
- SurrealDB 3.2.4 matches the latest stable patch listed by the vendor at audit
  time: <https://surrealdb.com/releases/3.2>.
- Runtime roles do not provide row-level tenant permissions for system users:
  <https://surrealdb.com/docs/learn/security/authorization/permissions-and-row-level-security>.
