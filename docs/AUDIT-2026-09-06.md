# Security and product audit — 2026-09-06

Scope: Zig/Zap backend, SurrealDB repository, browser controller and WASM,
tests, CI, deployment files, and read-only inspection of task.micutu.com.
Production accounts are not used for destructive tests. Findings below begin
as source/configuration observations; reproduction and remediation evidence is
recorded as each stage completes. This is not a claim that all vulnerabilities
have been found or that an external penetration test has been completed.

## Priority findings

| ID | Severity | Evidence at baseline 958ea41 | Consequence / action |
| --- | --- | --- | --- |
| S01 | Critical impact, conditional on code execution | systemd runs as `micu`, a Docker group member; Docker socket is group writable and not hidden from the unit | Application compromise can reach host administration and other applications. Move to a dedicated service identity and isolated release directory. |
| S02 | High | `verifyCsrfToken` accepts any `Bearer ` header before checking the cookie, while authentication prefers the cookie | Mixed credentials bypass the session's CSRF validation. Require CSRF whenever the session cookie is present. Browser exploitation depends on origin/CORS and request context. |
| S03 | High | Reset token is read before hashing; password UPDATE predicates only on user ID; session revocation is separate and best effort | Concurrent uses can both succeed; a partial failure can leave old sessions valid. Consume the token and revoke sessions in one transaction. |
| S04 | High | Parent creation checks write access but not workspace equality; deletion deletes all rows with that parent | A member of two workspaces can create a cross-workspace dependency that lets another workspace's writer delete the child. Enforce same-workspace parentage and scoped deletion. |
| S05 | Medium | Update passes `assignee_id` straight into the database, unlike create | Task assignment can point to an outsider or nonexistent account. Validate membership on both paths. |
| S06 | Medium | Every successful PUT of a completed recurring task spawns a new task | Editing notes or retrying completion creates duplicate work. Make recurrence creation atomic and idempotent. |
| S07 | Medium | API does not emit `Cache-Control: no-store` | Account/task/export responses lack explicit protection from private or intermediary caching. Add at backend and proxy. |
| S08 | High operational | Integration cleanup kills listeners by port, even after refusing an occupied port; smoke response uses a shared `/tmp` filename | Tests can stop another service or overwrite a symlink target. Track only owned PIDs and use private temporary files. |
| S09 | High impact | Application database credentials are root-level | Query or application compromise has unnecessary database administration scope. Separate runtime and migration identities. |
| S10 | Medium | SQL HTTP client retries all operations after ambiguous transport errors | Non-idempotent writes can be replayed. Remove automatic write retries. |
| S11 | Medium | Schema initialization continues after exhausting failures; task-list DB failure returns success with an empty array | Broken deployments and outages can look healthy or look like data loss. Fail startup closed and surface errors. |
| S12 | Medium | Signup explicitly says `Email already exists` | Account enumeration remains possible despite SECURITY.md claiming uniform signup responses. Redesign registration response/session flow before claiming protection. |

## Product and maintainability gaps

- Board completion state drifts on create and bodyless toggle.
- Nested subtasks can be created beyond the one level the UI renders/deletes.
- Editing a reminder deadline does not rearm reminder delivery.
- JSON export omits newer status/assignment/parent/recurrence fields.
- Mobile checks need narrow widths, board/editor states, dark theme, keyboard
  focus and long content. The current WASM assertion only checks API presence.
- Saved views, Today/Upcoming, useful empty/error states and offline metadata
  parity are higher value next steps than adding unrelated framework tooling.
- README describes an app+DB Compose stack, but Compose starts only the DB.
  Deployment examples use obsolete Zig and database versions. npm lockfile is
  ignored; CI dependencies/actions are not all pinned by content digest.
- Invitation acceptance, account deletion and several permission checks span
  multiple DB statements without a transaction; race tests need expansion.
- Quotas, pagination, durable mail delivery, backup restore evidence, alerting,
  MFA/passkeys and recovery procedures need tracked work.

## Threat model and incident readiness (ciso-review)

Top risks: elevation of privilege through the runtime Unix identity; tampering
across workspace boundaries and credential races; denial of service from
password hashing, unbounded account/workspace growth and database requests.

Worst case: account email addresses, password hashes, task contents, workspace
membership and secrets readable by the service identity; with Docker access,
other services on this VPS may also be affected. User count, incident cost and
annualized loss are unknown; no invented financial estimate is appropriate.

Detection observed: systemd/nginx logging and protected metrics. Alert routing,
current mean detection time and a tested on-call procedure are not established
by repository evidence. Target: alert within 5 minutes on sustained errors,
restart loops or abnormal authentication failures; name the operator and test
delivery before calling this implemented.

Vendors/components: VPS hosting, Cloudflare, SurrealDB, Zap/facil.io, SMTP,
GitHub Actions and test browser distribution. No new data vendor is proposed.
Contracts, data-processing agreements and regulatory scope are not established
by source inspection. An incident involving personal data requires a factual
assessment of applicable notification duties, not an automatic claim of
compliance.

Verdict: mitigate confirmed findings, verify in isolation, preserve a rollback
release and rehearse the incident procedure before production promotion.

## Verification log

- Live HTML uses CSP without `unsafe-inline`, HSTS, nosniff, frame denial and
  Cloudflare proxying. Direct unauthenticated task read returns 401.
- Backend and database listen on loopback. `nginx -t` succeeds and the active
  task vhost matches its versioned copy.
- `.env` and its backup are mode 0600 and Git-ignored. No contents are included
  in this report. No destructive live exploit has been attempted.
- SurrealDB 3.2.4 matches the latest stable patch listed by the vendor at audit
  time: <https://surrealdb.com/releases/3.2>.
- Runtime roles do not provide row-level tenant permissions for system users:
  <https://surrealdb.com/docs/learn/security/authorization/permissions-and-row-level-security>.

### Application remediation

The original binary passed all 37 existing smoke checks but failed 13 of 19
new security/correctness checks. The patched binary passes 37/37 smoke and
19/19 new checks against a disposable SurrealDB 3.2.4 instance.

Additionally confirmed (S13, High): a workspace member could DELETE an owner's
`workspace_members` record through `/api/tasks/:id`. The task access helper
accepted other tables with `user_id`/`workspace_id` fields. Both routing and the
repository now enforce the `tasks:` record type; the exploit is in the suite.

Addressed in code: S02–S08, S10, S11 and S13. Password resets consume their
token and revoke sessions in one transaction. Task completion and successor
creation share a transaction with a one-time marker and version check.
Already-completed recurring tasks are marked during migration to prevent
duplicates on later edits. Missed recurrence dates advance to the next future
occurrence; daily/weekly preserve cadence, monthly clamps calendar days.
Legacy cross-workspace child links are not deleted by foreign parent removal;
repairing existing orphan links remains a separate data review.

Source-level authorization checks still precede some mutations. Concurrent
membership revocation and invite consumption need further transaction coverage;
these are not claimed fixed by the checks above. No new production deployment
has been performed at this stage.

### Runtime isolation preparation and recovery — 2026-09-07

- Added database-level Basic authentication headers, a migration-only startup
  mode and schema-only runtime checks. Integration now migrates as root but
  serves as a database EDITOR. Conflicting transactions return an explicit
  retry/refresh error; they are not silently replayed.
- Added supplied-Origin and JSON-content-type checks to prevent cross-origin
  login/signup form submissions. Production no longer accepts legacy plain
  session cookies alongside the `__Host-` cookie.
- Prepared a dedicated Unix identity, root-owned release path, inaccessible
  Docker/admin sockets and memory/task limits in the versioned service unit.
  nginx's private API cache policy also covers proxy-generated errors.
- Administrative helper creates private exports, verifies a scoped runtime
  credential cannot run `INFO FOR ROOT`, and refuses nonempty/source restore
  targets. Fresh pre-deploy export: 30,740 bytes, root-only mode 0600.
- Restored the export into an authenticated disposable SurrealDB 3.2.4 memory
  instance with fresh random credentials. Account/task/session counts matched;
  the instance was removed afterwards. This verifies importability/counts,
  not a full content checksum or recovery from destruction of the VPS.
- Incident desk walkthrough covered leaked runtime credentials, faulty binary
  rollback and database loss. See the runbook for results and the unresolved
  operator/alert-delivery gap. No real notifications or production-account
  mutation tests were performed.
- Unit suite: 45/45; ReleaseSafe smoke 37/37 and security regressions 23/23,
  including simultaneous completion and monthly catch-up. npm audit reports
  zero advisories for the locked browser
  test dependency; this does not scan Zig, C, system packages or all supply
  chain components. CI now uses `npm ci`. Secret-file path history contains
  only `.env.example`, not a committed production `.env`.

S01/S09 promotion evidence and the final combined regression totals are
recorded separately after deployment, not inferred from configuration files.

### Daily workflow and mobile verification

- Added Today and Next 7 days filters using local calendar boundaries. Browser
  datetime inputs are converted to UTC before API writes; an unchanged overdue
  deadline no longer prevents an unrelated task edit.
- Named views persist search, filter, tag, sort and list/board choice per
  account/workspace on the current device (maximum 12). They are not a server
  sync feature. Sort preference is also remembered per scope.
- API refresh failures keep the last loaded tasks with a retry action. Logout
  clears private visible state and late list responses cannot restore it.
- Narrow task cards move actions below content; editors span the card;
  subtask inputs, board buttons and bottom safe areas fit mobile screens.
- ReleaseSafe browser suite: 59/59, including actual WASM instantiation,
  saved views, UTC dates, retry behavior, logout response race, list/board at
  320/390/768/1440 px in light and dark themes and a readable 320 px editor.
  Mobile/desktop captures were visually inspected. This is Chromium evidence,
  not a complete cross-browser or assistive-technology accessibility audit.
- Offline storage still lacks metadata parity (notably the Doing column), and
  screen-reader, zoom, localization and full synchronization remain backlog.

### Pre-promotion startup defects (S14/S15)

The first dedicated-user canary refused to listen; the original public service
remained healthy and was not replaced. Startup diagnostics also reported
double frees when process environment values replaced `.env` values.

- S14, High operational/memory safety: configuration replacement freed the
  original StringHashMap key even though the map retained it, producing a
  dangling key, double free and a leaked replacement key. `getOrPut` now retains
  the existing key and frees only the duplicate key and superseded value.
- S15, Medium operational: a Zig slice containing the bind address was passed
  to the C listener without a terminating NUL. The listener now owns an
  explicitly terminated copy for its entire lifetime.
- A duplicate-key unit regression was added. The disposable integration
  harness now also loads a synthetic `.env`, overrides selected values through
  the environment, and takes the bind address from the file. This covers the
  configuration shape the environment-only tests previously missed.

The failed canary was stopped. Its release was never promoted; migration 011
was already applied and is additive/backward-compatible. No database rollback
or deletion of production data was performed.

### Production promotion — 2026-09-07, Europe/Bucharest

Promoted application source `973767a` at 02:40 EEST. Current release:
`/opt/taskmanager/releases/20260907-973767a`, via `/opt/taskmanager/current`.
Only the taskmanager unit and its task nginx vhost were replaced; shared nginx
snippets already matched the repository. The failed first canary is retained
under `/opt/taskmanager/failed-canaries`, not as a rollback candidate.

Observed verification:

- Canary and live process both use UID 993/GID 973 (`taskmanager`) with only
  that group, `NoNewPrivs=1` and seccomp filtering. Inside the mount namespace,
  Docker/admin sockets and `/home/micu/taskmanager/.env` are unreadable; the
  root-owned release executable is not writable. Memory limit 1 GiB, task
  limit 128, four request threads, zero automatic restarts at verification.
- Runtime database authentication succeeds but `INFO FOR ROOT` is denied.
  Administrative credentials remain separate. This mitigates S01/S09's
  excessive privilege, not the residual all-tenant database access risk.
- Local and public `/api/ready` return ready/connected; unauthenticated public
  task reads return 401 with `Cache-Control: no-store`. HTML is 200 with strict
  CSP/HSTS and Cloudflare DYNAMIC; a dotfile request is 403 with security headers.
- nginx configuration validates. The public app.js/style.css hashes match the
  release. A read-only public mobile browser visit loads WASM and new controls,
  with no page overflow or uncaught JavaScript errors. No live signup, task
  mutation or test email was used for this verification.
- Final suites: **46 unit + 37 smoke + 23 security + 59 browser checks passed**
  on ReleaseSafe application builds with file-plus-environment configuration.
  Test listeners/containers and the canary are stopped.
- Protected pre/post-deploy exports, former unit/vhost, and legacy static files,
  executable and matching library are retained under
  `/var/backups/taskmanager/20260907-hardening` (root-only parent). Post-deploy
  export is 31,246 bytes. Restore-count evidence above concerns the pre-deploy
  export; no off-host backup or notification drill is claimed.

Remaining priorities: signup enumeration; transactional permission revocation,
invite acceptance and account/password changes; quotas/pagination; durable
mail and authentication event detection; named alerts; encrypted off-host
backup; MFA/passkey recovery; offline parity and accessibility. Cloudflare
injected inline challenge code may conflict with the strict CSP; do not fix it
by globally allowing unsafe inline scripts. A full independent pentest,
dependency/host scan and cross-browser accessibility audit remain advisable.
